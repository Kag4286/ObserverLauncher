# v4.4.0 plan — Remote Web GUI + remote hardening + stability fix

> Status: SCOPED (2026-10-10). Tick an item only when written AND verified (`npm test` + `npm run test:e2e`).
> 4.4.0 = a browser dashboard for Remote access, the three remaining remote LOW findings, and a
> stability false-positive fix. Two tracks are independent; the GUI is the headline.

## Context

Remote access (3.3.0) is a loopback HTTP **API** — it returns JSON only (`docs/remote.md`). Users who
open `http://127.0.0.1:<port>/` in a browser see `{"ok":false,"error":"unauthorized"}` and no page.
4.4.0 adds a small **read-mostly web dashboard** served by the same remote server, plus closes the
remaining LOW findings from the 4.3.0 audit, plus stops a manual Stop from being logged as an
"unstable run".

Design gate (unchanged): the remote server stays loopback-first, token + IP allowlist + read-only
subset. Write/destroy/install are NEVER reachable remotely. MCP stays a separate loopback server.

## Track A — Remote Web GUI (headline)

Goal: open the remote address in a browser and see a real dashboard — status, console, players — and
(when Read-only is OFF) send a console command. Same URL works from a phone via Tailscale.

### A1. New files `src/remote-ui/`

- `index.html` — single page, no framework, no bundler (matches the project's plain-script ethos).
- `style.css` — uses DESIGN.md tokens (warm near-black canvas, `--brand` emerald, Manrope + IBM Plex
  Mono, `--r-*` radii, `--dur-*` motion). A small, self-contained token block (the page cannot import
  the renderer's CSS build).
- `app.js` — `fetch` calls, auto-refresh, token in `localStorage`, plus a self-contained i18n object
  with all **7 locales** (en, vi, es, pt-BR, de, ru, zh-CN). Language auto-detected from
  `navigator.language`, with a manual switcher.

### A2. `src/main/remote.js` changes

- **Static serving.** New routes, BEFORE the auth check but AFTER the Origin/Host guards:
  - `GET /` and `GET /ui` -> `src/remote-ui/index.html`
  - `GET /ui/style.css` -> the CSS
  - `GET /ui/app.js` -> the JS
  Serve ONLY these three known files — never build a path from user input (no traversal). Read once
  and cache in memory; re-read never (the files ship with the app).
- **Origin guard relaxation (SECURITY — review carefully).** The current guard rejects ANY request
  carrying `Origin` (anti-CSRF / DNS-rebinding, `remote.js:85`). A same-origin `fetch` POST from the
  new page sends `Origin: http://127.0.0.1:<port>`, so the page could not call `/command`. Relax to:
  - No `Origin` header -> allowed (the real CLI/curl client; unchanged).
  - `Origin` header whose host:port matches the request `Host` -> allowed (same-origin page).
  - Any other `Origin` -> **403** (unchanged cross-origin defense).
  Keep the existing Host-header guard and the token/allowlist order intact. Add a regression test for
  all three cases.
- Token / allowlist / read-only behavior is UNCHANGED. The page is served without auth (it carries no
  secret), but every data call needs `Authorization: Bearer <token>` exactly like curl.

### A3. GUI content (read-mostly)

- Header: title, status pill (Running / Stopped / Starting / Stopping), active instance name.
- Status card: software + version, Java, serverPath, TPS/players when available (reuse `/status`).
- Console: last N lines from `/console`, auto-scroll, manual refresh + a pause toggle.
- Players: online / whitelist / ban / op from `/players`.
- Instance selector: from `/instances`; every read adds `?instance=<id>`.
- **Command box** — shown ONLY when the token's server has Read-only OFF (the page learns this from a
  small `GET /status` -> include readOnly in the payload, or a new `GET /ui/config`). Server still
  enforces 403 when read-only is on (defense in depth).
- Token entry: a first-run prompt to paste the token (from the app's Reveal/Copy); stored in
  `localStorage`; a "forget token" button. Never put the token in the URL.

### A4. Tests `tests/remote-ui.test.js`

- `GET /` returns the HTML; `GET /ui/style.css` and `/ui/app.js` return the assets.
- Same-origin `Origin` on POST `/command` -> allowed; cross-origin `Origin` -> 403; no `Origin` ->
  allowed (curl).
- A traversal attempt on the static path (`/ui/../remote.js`) -> 404, never serves source.
- Command box gating: `/command` still 403 when read-only is on.

## Track B — Remote LOW findings (from the 4.3.0 audit)

### B1. Constant-time token compare
`remote.js:104` and `src/mcp/server.js:243` compare with `auth !== \`Bearer ${token}\``. Replace with
`crypto.timingSafeEqual` over equal-length buffers (guard length first; a length mismatch returns
false without leaking via throw). Low real-world risk (loopback/Tailscale + 48-hex token) — do it for
correctness. Apply to BOTH servers so they cannot drift.

### B2. Rate limit the remote server
MCP has a 60/min per-client bucket (`server.js:209`). The remote server has none. Add the same token
bucket keyed by client IP (loopback/Tailscale), returning 429 when exceeded. A token-holder is trusted,
but a leaked token should not allow unbounded hammering.

### B3. Do not leak `e.message` in 500 responses
`remote.js:109` `run()` returns `{ error: e?.message }` raw. Return a generic message to the client and
log the detail server-side (the audit/log path), so internal paths/stack hints do not leave the box.

## Track C — Stability false-positive fix

`stability.js` classifies a run as `unstable` when it lives < 120s, and `noteExit` is called on EVERY
exit — including a user-requested Stop. Three quick Start->Stop cycles therefore log
"unstable 3 runs in a row - rollback recommended" even with no crash (`server-lifecycle.js:430-439`).

- `classifyRun(record, now, opts)`: accept `opts.manual`; when true return `'manual'` (a distinct
  outcome that neither increments nor resets the streak).
- `noteExit(instanceId, { code, manual })`: pass `manual` through; on `'manual'` leave `unstableStreak`
  and `lastOutcome` untouched (so a real crash streak is not erased by a clean manual stop).
- `server-lifecycle.js`: pass `manual: wasManual` (already read at line 430) into `noteExit`.
- `tests/stability.test.js`: extend with a manual-stop case (does NOT count unstable) and keep the
  crash-streak case.

## Risks / gotchas

- The Origin relaxation is the one security-sensitive change — keep the cross-origin 403 and cover it
  with a test (fetch drops Host on some paths; use raw http.request like `remote-server.test.js:90`).
- The GUI page cannot reuse the renderer's `i18n.js` (different build); it has its own small i18n — do
  NOT duplicate the whole app locale files.
- The page is served by the main process; it must NEVER read a file path from the request (traversal).
- Motion: the GUI is a separate page — it is NOT covered by `tests/motion-tokens.test.js` (that scans
  `src/renderer/css`). Still follow the DESIGN.md duration tokens by hand; no literal ms.
- New visible strings are GUI-local (not app locales) — the app's `tests/i18n.test.js` does NOT cover
  them, so add a small check inside `remote-ui.test.js` that all 7 locales have the same keys.

## Out of scope (deliberate)

- No write/destroy/install over the GUI (only the read subset + the read-only-gated console command).
- No 6h/24h metrics, no accent-color picker, no code-signing (separate items).
- MCP stays loopback-only; the GUI is Remote-access-only, never MCP.
