## Diagnosis (LIVE-PROBED 2026-09-24, not guessed)

### Download bugs found by probing every resolver
| Software | Resolver | Live result |
|---|---|---|
| vanilla | vanilla.js | OK (26.3) |
| fabric | fabric.js | OK (26.3) |
| purpur | purpur.js | OK (26.3) |
| leaf | leaf.js | OK (26.2) |
| velocity | papermc.js | OK |
| **paper** | papermc.js | **FAILED** "No stable paper build for 26.3 (newest: ALPHA)" |
| **folia** | papermc.js | **FAILED** "No stable folia build for 26.2 (newest: BETA)" |
| forge/neoforge | forge.js | runs installer; NOT probed (needs Java) |
| spigot | spigot.js | compiles via BuildTools; NOT probed |

- **Paper/Folia root cause:** wizard defaults to `versions[0]` = newest version, which PaperMC
  often ships only as ALPHA/BETA right after an MC release. The adapter (correctly) refuses
  non-stable builds, so "Latest" failed. **FIXED (option 1a):** `papermc.js` now walks the newest
  N versions and picks the newest with a STABLE build (`resolveStableVersion`), returns per-version
  stability (`listFillVersionsWithStatus`), and the error names the newest stable. Verified live:
  paper -> 26.2-83, folia -> 26.1.2-6.
- **NeoForge root cause:** maven `<latest>` = `26.3.0.16-beta` (a BETA, and for the newest MC, not
  the user's). The wizard shows all 1723 versions unfiltered, so picking "Latest" installs a beta
  for the wrong MC -> installer fails. FIX PENDING (needs the version step to pick MC first for
  forge/neoforge, then filter that MC's line).

### Renderer bug (found in DevTools)
- `Uncaught (in promise) Error: prompt() is not supported.` — `renameInstancePrompt` called
  `window.prompt`, which Electron's sandboxed renderer does not support. **FIXED:** new in-app
  `promptDialog()` (00-core.js) + `#promptModal` (index.html) + CSS; rename now uses it.
