# v6.0.0 plan: Bedrock crossplay, player and world tools, integrations

> Status: SCOPED (2026-10-16). Tick an item only when written AND verified (`npm test` + `npm run test:e2e`).
> v6.0.0 is a major release. The headline is Bedrock crossplay that works end to end: repair the
> Geyser config in one click, and add a second tunnel provider (Pinggy) that carries the Bedrock UDP
> tunnel the free Playit plan cannot. Around that, the release widens the app on three fronts:
> player and world tooling (3D skin, inventory, analytics), content management depth (update and
> conflict checks, permissions, datapacks), and integrations (Discord, cloud backup, Prometheus).
> Advanced users get longer metrics history, crash analysis, a three-way update policy and RAM
> presets. Hardening and polish close the release.

## Context

5.7.0 detects Geyser and reports config problems, but it only reads. The user still opens
`config.yml` by hand, and the free Playit plan cannot expose Java TCP and Bedrock UDP at the same
time. Crossplay is detected but not finished. v6.0.0 finishes it and then broadens the product.

The plan is split into nine tracks plus a spike track. The spikes run first because their result can
change a track's design. No product code is written against a guessed interface.

- Track A: Bedrock crossplay. Geyser one-click fix, Pinggy as a second provider with fallback, wizard hint.
- Track B: player and world tools. 3D skin, inventory, ender chest, resource packs, analytics, world map extension, world operations, waypoint sync.
- Track C: content management. Update checker, bulk update with rollback, conflict detector, permissions editor, datapack UI.
- Track D: observability. Metrics beyond 24h, crash analyzer, TPS anomaly detection, memory-leak watch, Spark integration.
- Track E: multi-server and proxy. Velocity setup, start-all, groups and tags, cross-instance dashboard.
- Track F: integrations. Discord webhook, cloud backup, generic webhook, Prometheus endpoint.
- Track G: config depth. RAM presets and MOTD preview, properties history, JVM preset library, game-rule editor, config templates.
- Track H: hardening and polish. Transactional modpack install, hardened downloads, delete dialog, update policy, fix sweep, UI polish.
- Track I: developer surface. CLI extension, Docker compose export, headless REST, event hooks.

Design gates that do not change: the tunnel provider is a fixed enum (no renderer string reaches a
command line); a config write always keeps a backup; metrics stay per-instance on disk; the MCP tool
registry and `bridge.js` STATIC_TOOLS stay in sync; the project stays plain Electron with no bundler.

## Legal and asset rules (apply to Track B and Track C)

These are contract rules, not preferences.

- Never bundle Mojang assets in this repository. No textures, models, sounds, or language files.
- The app MAY read files on the user's machine at runtime: the game jar, mod jars, a resource pack
the user chose, and the player `.dat` files. The `tex://` protocol already works this way (it fetches
item icons to the user's machine from the public PrismarineJS mirror and bundles nothing).
- Any feature that generates or renders from game assets sits behind a one-time EULA acknowledgement.
- The app never redistributes a resource pack or a skin. It reads them for display on the same machine.
- A fetch that fails falls back to a neutral placeholder, never to a broken image or a blank panel.

## Spike track (run first)

Each spike is a throwaway script. It answers one question and writes down the exact interface it
observed. If a spike fails, stop and report; do not guess the interface and do not continue the
dependent track.

- SP1 (Pinggy): run the Pinggy CLI or Node SDK against a local TCP socket and a local UDP socket.
  Capture the exact command shape, the public address output format, the free-tier time limit, and
  how reconnect is signalled. Decides Track A2.
- SP2 (skin fetch): resolve a UUID to a skin through the Mojang session server, and confirm the
  texture URL and the rate limit. Decides Track B1.
- SP3 (modded icon): open three real mod jars and try to read an item texture plus its model json.
  Confirm how many mods expose static textures. Decides how far Track B1 and Track C1 go.
- SP4 (3D render): render a player model in a bare canvas without a bundler. Confirm WebGL is
  available in the renderer and decide WebGL versus a software renderer. Decides Track B1.
- SP5 (LuckPerms storage): read a LuckPerms data folder and confirm the storage format for the
  installed version. Decides Track C4.
- SP6 (cloud SDK): confirm whether an S3 or Google Drive upload can be done without a heavy SDK, or
  whether a new dependency is acceptable. Decides Track F2.

## Track A - Bedrock crossplay (headline)

Goal: a user with a Geyser modpack goes from "Bedrock cannot join" to "Bedrock joins" without
editing YAML by hand.

### A1. Geyser one-click "Apply fix" - DONE (v6.0.0; needs manual test on a real Geyser config)

Today `src/main/geyser.js` `inspectGeyser()` returns `issues[]`, each `{ level, key, message, fix }`.
The panel lists them. Add a writer that repairs the SAFE issues in place.

- New function `planGeyserFix(root, inspection)` returns a list of `{ key, path, from, to }` edits it
  can make, or an empty list when nothing is safely fixable.
- New function `applyGeyserFix(root, plan)`: for each edit, rewrite the ONE line for that key, keeping
  every other line, comment and blank line untouched. Returns `{ ok, changed[], backup }`.
- CRITICAL: `parseSimpleYaml()` is lossy (it drops comments and list items). Do NOT re-serialize the
  parsed object; edit at the line level. Find the key path by indent and replace only its value text.
  This is the sharpest edge in the release.
- Fixable keys (safe, unambiguous): `bedrock.clone-remote-port` to `false`,
  `remote.auth-type` to `floodgate` (only when Floodgate is present),
  `advanced.bedrock.use-haproxy-protocol` to `true`, and `bedrock.port` to `19132` (only when the
  user explicitly asks, because it changes which local UDP port the tunnel must match).
- NOT auto-fixed: the query-port clash (a different file, `server.properties`) and the Java version
  issue (needs an install). Those stay as instructions.
- Backup: copy `config.yml` to a timestamped sibling before any write, then write the new content with
  `fs-utils.writeFileAtomic`. Report the backup path so the panel can show the reversibility cue.
- Confirm: this writes a file the user owns, so route it through the confirm pattern used by other
  writes. Not silent.
- IPC: new channel `geyser:apply-fix` (preload + main + arch test).
- Renderer: an "Apply fix" button in the Geyser panel, shown only when the plan is non-empty.
- MCP: add a write tool `apply_geyser_fix` (risk write, asks once, respects `mcpReadOnly`). Add it to
  both `src/mcp/tools.js` and `src/mcp/bridge.js` STATIC_TOOLS.
- Tests `tests/geyser.test.js` (+N): a plan for each safe key; a line-level edit that preserves
  comments and unrelated keys; a refuse-to-edit case when the key path is ambiguous; backup created.

### A2. Pinggy as a second tunnel provider (full) - DONE + VERIFIED IN APP (SP1 passed; manual test LIVE)

> DECISION CHANGE from the first draft (with the user): Pinggy runs ALONGSIDE Playit (Playit = Java
> TCP, Pinggy = Bedrock UDP), NOT as a replaceable provider. So there is NO `PROVIDERS` change and
> NO auto-fallback: the Geyser panel offers a Pinggy button explicitly. See pinggy-tunnel.js.

Playit's free plan cannot expose TCP and UDP at once, so crossplay needs a second UDP tunnel. Pinggy
carries UDP. This item is gated by SP1.

- A2.1 Provider enum: `PROVIDERS` in `tunnel.js` becomes `['playit', 'pinggy']`.
- A2.2 New adapter `src/main/pinggy.js`: locate the binary, build argv for a TCP or UDP tunnel to a
  local port, parse the public address, start and stop. Mirror the structure of `tunnel.js` but do NOT
  copy it; extract the shared parts (binary lookup, address shape) into a helper.
- A2.3 `src/main/tunnel-manager.js`: automatic fallback. When the Playit agent reports it is over its
  free agent limit, or fails to start, and the instance needs a UDP tunnel, switch to Pinggy and log
  the reason. Keep the decision in the manager (pure, testable).
- A2.4 Per-instance provider choice (default Playit). Add the key to `PER_INSTANCE_KEYS` and the per
  instance field trio in `context.js` if it lives on ctx.
- A2.5 Renderer: a provider selector in the tunnel panel and a status line that names the active
  provider. Reuse existing tunnel status keys where possible.
- A2.6 Settings: `pinggyPath` (global, like `playitPath`).
- Tests: `tests/tunnel.test.js` (+N) for provider validation and fallback decision; a pure
  `tests/pinggy.test.js` for the argv builder and the output parser.

### A3. Crossplay hint in the wizard - DONE (static note on Review for Geyser-capable software; the
wizard does not accept a modpack, so detect-from-pack was replaced with a software-based note)

When a chosen modpack or template includes Geyser or Floodgate, the New Server wizard shows a short
plain-language note: crossplay needs a Bedrock UDP tunnel, and the app will offer to set it up after
the first start. One wizard step addition plus keys.

## Track B - Player and world tools

Goal: a player is an entity with a real face and real items, not a row in a list. Gate: SP2, SP3, SP4.

### B1. Player inspector

- B1a 3D skin render. Resolve the UUID to a skin (SP2), draw the player model on a canvas (SP4).
  Support slim and classic models, and the outer layer.
- B1b Worn armor and off-hand. `readPlayerData()` already reads the new layout (equipment separated,
  lowercase count). Render the armor pieces on the model.
- B1c Inventory and ender chest. A grid with real item icons. Vanilla icons come from `tex://`.
  Modded icons come from the mod jar when SP3 shows they are static, else a neutral placeholder.
- B1d Resource pack selector. The user picks a resource pack (a zip). The app reads it at runtime and
  overrides item and block icons from it. Nothing is redistributed. Falls back to `tex://` when the
  pack has no override.
- B1e EULA gate. A one-time acknowledgement before any generate or render from game assets.
- B1f Fallback avatar. When the skin cannot be fetched, show the initials avatar already used for
  instances. Never a broken image.
- One-click actions: op, whitelist, kick, ban, in the inspector (reuse existing IPC handlers).
- Tests: a pure skin-property parser, a model part list, and an inventory to grid mapping.

### B2. Player analytics

- Playtime per session and total, first and last seen, activity by hour and weekday, top players.
  Read from the stats files and the session log. Pure aggregation, unit-tested.

### B3. World map extension

- Cave mode (a Y slice), Nether and End dimensions, entity markers (mob, item frame, mod waypoint),
  and PNG export. Reuse `worldmap.js` and the existing canvas. Never animate the canvas.

### B4. World operations

- Rename a world, edit the display seed, delete a single dimension, import and export a world between
  instances. Each is a file operation behind a confirm, with a backup of the world folder first.

### B5. Waypoint sync

- Share waypoints between instances, and import from the Xaero and JourneyMap formats. Pure parsers
  plus a small merge UI.

## Track C - Content management depth

### C1. Mod and plugin update checker - DONE (shipped in 3.3.0, not new in 6.0.0; scope reduced to manifest-tracked content)

- `content-updates.js` `checkUpdates()` reads `observerlauncher-manifest.json`, keeps only entries whose file still exists in `mods/` or `plugins/`, and resolves each through the SAME marketplace resolver the installer uses. `applyUpdates()` downloads the newer build, backs up the old file to `observerlauncher-content-backups/`, and refuses while the server runs.
- Renderer: a `#contentUpdatesPill` badge on the Content tab ("N updates available"), a `→ latest` version badge and per-row Update button, and a `Check updates` button. All wired in `01-content.js` since 3.3.0.
- KNOWN LIMITATION (deliberate, out of 6.0.0 scope): a jar dropped into `mods/` or `plugins/` by hand has no `projectId`/`source` in the manifest, so it is reported as `status: 'unknown'` with the reason "installed before update tracking (no project id)" instead of a false 'current' or a guessed update. Matching an untracked jar to a marketplace project through jar metadata is approximate (mod id does not map one-to-one to a marketplace project), and Track C stays read-only-report in this release, so this is deferred rather than half-done.

### C2. Bulk update with rollback

- Update many mods in one pass, create a backup first, and roll back if the server does not start.
  Reuse the stability record to decide success.

### C3. Conflict detector - DROPPED (deliberately out of 6.0.0 scope; the MCP already covers this via `check_mod_compat` and `doctor_report`. Keeping deep diagnostics in MCP preserves its distinct value over the GUI.)

- Duplicate mods, version mismatch, loader mismatch, and missing dependency. Reuse `mod-metadata.js`
  and `modpack-resolve.js`. Report only, with a fix hint.

### C4. Permissions editor (LuckPerms)

- Read and write the LuckPerms storage, with a group and permission tree UI. Gate: SP5. Storage
  format differs by version, so support the format the spike found and refuse the others with a clear
  message.

### C5. Datapack manager UI - DONE (enable/disable/delete were already in the shared content list; new: a per-row Validate that checks pack.mcmeta against the server MC, a per-row Extract that unzips a .zip datapack, and a Datapack load-order panel that reorders level.dat DataPacks.Enabled with backup)

- `datapack.js` exists but has no dedicated UI. Add enable, disable, reorder, and delete, with a
  confirm on delete.

## Track H - Hardening and polish

### H1. Transactional modpack install

- Reject zip or manifest entries whose path escapes the server root. On failure, roll back the whole
  change set: restore overwritten files from the pre-install backup and remove files the failed
  install created. Record a manifest of what was touched so rollback is exact.

### H2. Hardened downloads

- `http.js` `download()` already has an `ACTIVE_DOWNLOADS` guard. Add: retry only transient failures,
  fail fast on permanent ones, verify the final size against content-length when known, and never
  leave a partial file (write to a temp name, rename on success, delete on failure).

### H3. Themed delete dialog

- Deleting an instance offers "Delete profile only" or "Delete profile and files". Destroy action, so
  it always confirms. New keys `cf.deleteProfileOnly`, `cf.deleteProfileFiles`.

### H4. Update policy

- Replace the `autoCheckUpdates` boolean with a three-way policy: `auto` (check and download, prompt
  to install), `ask` (check on startup, ask before download), `off`. Keep reading the old boolean as a
  fallback for one release so an existing profile is not lost. New keys `upd.mode`, `upd.modeAuto`,
  `upd.modeAsk`, `upd.modeOff`.

### H5. Fix sweep - DONE (found + fixed a real replay-animation bug in renderTunnelOverview; the other lists already had signature guards)

- Run `todo_scan` and fix the small issues known to recur: a button-based control that reads with the
  OS default style, and a list that replays its entry animation on every `refreshUI()`. Confirm each
  with `read_file` before editing.

### H6. UI polish - PARTIAL DONE (clickable console player names shipped; startup splash + layout-shift reservation deferred as low-value vs risk)

- A short startup splash while the app boots, guarded by `prefers-reduced-motion` and Lite mode.
  Reserve space on load to reduce layout shift (the metric hero and the rail badges). Clickable player
  names in the console, behind a signature check so the console is not rebuilt on every line.

## Risks and gotchas

- A1 line-level YAML edit is the sharpest edge. `parseSimpleYaml` loses comments, so never re-emit
  from the parsed object. Test with a real Geyser `config.yml` that has comments.
- The Pinggy, skin, modded-icon, 3D-render, LuckPerms and cloud interfaces are unverified until their
  spike passes. Do not write product code against a guessed interface.
- New IPC channel and any new per-instance field must be added in every place the guards check
  (preload + main + arch test; freshInstState + INST_FIELDS + arch MIGRATED list).
- A new MCP tool must land in both `tools.js` and `bridge.js`.
- `switch_root` can revert between turns: `get_root` first.
- Apply edits to locale files with unique, byte-exact anchors. `apply_patch` is atomic, so one bad
  anchor cancels the whole batch.
- Do not duplicate the Playit and Pinggy adapters, or the item-icon paths. Extract the shared parts
  and let `tests/no-dup.test.js` pass.
- Legal: no Mojang asset is bundled, ever. Every generate or render from game assets sits behind the
  EULA gate. A failed fetch falls back to a placeholder, never a broken image.
- New runtime dependency: none expected except possibly the cloud SDK in F2. SP6 decides; ask before
  adding it. The project otherwise stays on `prismarine-nbt` and `electron-updater` only.

## Out of scope (deliberate)

- No plugin sandbox or third-party extension runtime in this release (I4 is a light hook only).
- No code-signing change (a separate item).
- No write or destroy over the remote GUI.
- No bundler, no framework, no build step for development.
