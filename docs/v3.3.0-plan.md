## Track A — Remote management (security-first, gate hard)
> Carried verbatim from docs/v3.0.0-plan.md: DESIGN GATE = never expose MCP to the internet. MCP
> stays loopback-only forever. A thin remote API uses a stable long-lived token + per-IP scope +
> a READ-ONLY-ish subset (status/console/restart/players). NEVER expose DESTROY/install over a
> tunnel. Reuse rcon.js for live control; MCP stays internal. Prefer Tailscale over Playit.

- [ ] R1 token + settings foundation. `remoteToken` -> GLOBAL_SECRET_KEYS (secrets.js, safeStorage).
      New GLOBAL defaults in settings.js: `remoteEnabled:false`, `remoteReadOnly:true`,
      `remoteAllow:''` (comma-separated IPs). Global keys only -> NO settings migration (schema v4).
- [ ] R2 `src/main/remote.js` — a SEPARATE loopback HTTP server (not the MCP port). Long-lived
      token + per-IP allowlist on every request. Read-only-ish endpoints (status / console-tail /
      players) + safe actions via rcon.js (restart). Reuses callTool with cfg.readOnly + a tool
      allowlist so write/destroy can never run. Every call wrapped in ctx.runInInstance().
- [x] R3 outbound path DONE 2026-10-03: docs/remote.md (Tailscale preferred, Playit alt, advanced
      table, API table, security model). App never opens a port / ships TLS.
- [ ] (old) R3 outbound path: docs/remote.md — Tailscale preferred (real identity, no port), Playit
      documented as an alternative. The app NEVER opens a port or ships TLS itself.
- [ ] R4 tests + UI + release prep: security tests (bad token -> 401, IP outside allowlist -> 403,
      destroy blocked, read-only default on); Settings toggle + 7-locale keys; CHANGELOG + notes.

- Remote (A) and content lifecycle (B) are INDEPENDENT and can land in any order.

## Risks / gotchas
- Remote is the single biggest security surface: a long-lived token + allowlist is the whole
  defense. Default read-only ON; never expose write/destroy; never bind beyond 127.0.0.1.
- CB2 touches 5 install call-sites in 3 files -> re-run no-dup + the manifest tests.
- A new per-instance ctx field (if any) needs the 3-place edit (freshInstState + INST_FIELDS +
  arch-ctx-accessors MIGRATED).
- manifest schema is a DATA file, not settings -> do NOT add a settings migration for it.
