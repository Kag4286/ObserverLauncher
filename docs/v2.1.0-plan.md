## Why 2.1.0 (not bigger)
2.0.0 shipped multi-instance (the architecture headline). 2.1.0 is the next
single big thing for the MCP/AI user: an assistant that can actually ASSEMBLE a
working modpack (choose, verify, install in one confirmed batch) instead of
installing one item at a time. Everything else here is hardening/debt that rides
along; cloud/remote/TS stay out (see 2.0.0 plan 'Explicitly NOT doing').

## Theme A - MCP modpack intelligence

### Current gap (verified 2026-09-24)
- `install_from_market` accepts kind plugin|mod|datapack only - a modpack cannot
  be installed from the registry; the user must download a .mrpack manually.
- `list_market_versions` is Modrinth-only.
- `plan_modpack` (src/mcp/modpack-plan.js) checks item-vs-SERVER compat only
  (mc version, loader family, env.server==unsupported). It does NOT detect
  item-vs-item conflicts, does not dedup against content already in mods/plugins,
  and caps dependency depth at 2 (deps at depth 3+ silently dropped).
- CurseForge deps are surfaced (entry.dependencies) but never auto-installed
  (CF has no reliable required/optional table) - keep that behaviour.
- assemble_modpack has no size preflight and no rollback on partial failure.

### Work items
- A3 item-vs-item conflict detection: NEW pure fn `planConflicts(items)` in
  src/mcp/modpack-plan.js. Detects: same project different resolved version;
  multiple lib versions of the same dep name; Modrinth relationType
  'incompatible'. Returns { conflicts: [{ a, b, code, detail }] }. tPlanModpack
  merges these into the result + a top-level `conflicts` array.
- A4 already-installed dedup: tPlanModpack reads serverFiles(root) and marks
  each planned item `alreadyInstalled:true` when a file with the same resolved
  filename exists in the target folder (case-insensitive). Not an error - a hint.
- A5 deeper compat in itemCompat: (a) when a Modrinth mod lists fabric/quilt and
  the plan has no fabric-api, add warning 'fabricApiMissing'; (b) when the
  server root has velocity.toml / bungee config, add 'proxy' warning for
  server-side-only assumptions; (c) pass through a java requirement when the
  registry exposes one (else skip). Stable warning codes.
- A1 install modpack from registry: marketplace.resolveMarketDownload learns
  project type 'modpack' (Modrinth) -> returns the .mrpack download; tools.js
  tInstallFromMarket routes kind:'modpack' to a temp file + importMrpackFromPath.
  NEW tool `search_modpacks` (thin wrapper over search_marketplace with
  kind:'modpack'). bridge.js INSTRUCTIONS + STATIC_TOOLS updated.
- A2 multi-source versions: add Hangar + CurseForge branches to
  list_market_versions (Modrinth already there). Reuse searchMarket facets.
- A6 deps depth: raise the plan_modpack follow depth from 2 to 3, keep the
  seen-set cycle guard and capPlan budget (report trimmed count).
- A7 preflight + rollback: tAssembleModpack (a) sums dl.size when available and
  returns totalBytes + a >500MB warning before downloading; (b) records every
  created file and, on a mid-batch failure, returns the list so a follow-up
  delete_content can undo (no automatic delete - the user approves).
- A8 tests: tests/mcp-modpack-plan.test.js covering planConflicts, dedupeById,
  capPlan, itemCompat new codes; extend the bridge STATIC_TOOLS drift guard for
  search_modpacks.
